# 桌宠扩展开发与发布

## 独立角色：鲸鱼娘

主程序“设置 → 桌宠”可分别安装或卸载角色，并为已安装角色设置默认形象；它与桌宠右键菜单共用 `layout.json` 中的角色偏好。鲸鱼娘素材来源：[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，仅限非商业用途。

桌宠右键菜单中的“再开一只桌宠”可按已安装角色即时增加实例，“关闭这只桌宠”只关闭当前实例；全部关闭后恢复悬浮球。额外实例固定角色并将布局与缓存保存在各自的 `vpet/instances/角色-序号/`，以免多个窗口争写位置。旧版设置中的多开数量不会自动启动实例；更新时暂时关闭并恢复当前实例，退出时关闭全部实例。

每只桌宠右键“显示来源”可分别绑定主程序当前平台、已配置平台的默认账户或账户档案；选择保存在对应实例目录的 `display-source.json`。主程序继续独立采集所选来源，只向桌宠进程发送展示字段，不传递凭据。账户档案编辑或删除后立即丢弃旧快照，未指定来源的实例仍跟随当前平台。

桌宠右键菜单的“角色”中可选择 萝莉斯或鲸鱼娘，只显示已安装角色的形象缩略图。选择写入现有 `layout.json` 的可选 `character` 字段；旧布局及无效值优先使用 VPet，未安装时改用已有角色。鲸鱼娘源码保留参考提交的 106 段透明 WebM，构建时将全部动作转成真实 APNG 帧，发布包仅保留一个自定义动画测试样本；右键“鲸鱼娘动作”可按原分类点播。待机、转向、移动和分类动作遵循原权重连续播放，点击、拖拽及碰撞反馈使用真实动画，甩抛仅在松手前快速移动时触发。自定义 WebM 放入本地桌宠数据目录的 `main-animation/webm/`，同名文件覆盖包内动作；播放自定义素材需自行安装 FFmpeg。菜单图标使用原项目图片。两种角色的额度气泡均可选择对白框或简洁卡片；云朵样式已从界面移除。鲸鱼娘气泡的位置和尺寸按待机动画的不透明角色轮廓计算，避免被整张透明画布的留白推远。鲸鱼娘仅在屏幕左下角或右下角显示固定大小的卡片，放大缩小只调整角色；DeepSeek 卡片包含余额、峰谷及新增费用反馈，当前活动配置传来百分比额度时显示“额度”卡片，额度下降时播放动作并浮出减少的百分比。素材来源、固定提交、转码对应关系和非商用限制见 `THIRD_PARTY_NOTICES.md`。

余额档位从现有用量消息触发；DeepSeek 余额卡片只接收金额、费用、峰谷和账户变化标记，不接收凭据或账户标识。宿主还接受可选的 `{"type":"work_status","status":"thinking|working|result|waiting|success|error|null","text":"可选短句"}` 消息，主程序桥接可用 `VPetHost.update_work_status` 发送。当前主程序没有任务生命周期来源时不会生成虚构状态；状态来源接入后即可自动播放对应档位。

桌宠与主程序在同一仓库维护，分别打包、编号和发布。未安装、关闭或卸载桌宠不影响悬浮球、面板、主题、账户和用量功能。首次使用独立扩展需要安装支持扩展管理的主程序；之后在通信协议兼容时只更新桌宠即可。

## 修改边界

| 位置 | 职责与发布归属 |
| --- | --- |
| `pet_host/` | 桌宠窗口、交互、菜单、展示逻辑；随桌宠扩展发布 |
| `third_party/VPet/VPet-Simulator.Core/` | 随仓库维护的核心源码；随桌宠扩展发布 |
| `scripts/build_vpet.py` | 宿主编译、资源裁剪与依赖授权收集 |
| `ui/vpet_host.py` | 主程序通信桥；改变桥接能力需要主程序更新 |
| `core/pet_extension.py`、`updater/client.py` | 主程序的扩展安装、更新和兼容性检查 |
| `build/vpet-upstream/` | 固定版本动画下载缓存，不提交；资源变更通过构建脚本或仓库内资源维护 |

桌宠通过本机父子进程管道接收展示字段，不读取账户凭据。默认仍保留原有面板的全部入口；宿主异常时回到悬浮球。

## 气泡与提醒

右键菜单内配置额度展示方式、随机间隔，以及独立的喝水和休息提醒。默认保留贴边自动显示，生活提醒关闭；主程序设置页和协议版本不变。

悬停角色时按住 Ctrl 滚动鼠标滚轮，每档按 20 单位调整尺寸，范围仍为 160–320；右键菜单不再显示放大、缩小项，普通滚轮和拖动手势不触发缩放。

- 额度展示：贴边自动、悬停、随机、悬停＋随机、关闭。关闭偏好在重启后保留；手动勾选“显示额度气泡”可重新开启。悬停延迟 300 毫秒，离开角色和气泡后宽限 500 毫秒；随机间隔为 3–5、5–10（默认）、10–20 分钟，显示 8 秒，悬停可延长。
- 额度气泡样式：对白框（默认）或简洁卡片。偏好保存在 `layout.json` 的 `bubbleStyle` 字段；旧布局和无效值使用对白框。
- 喝水提醒：15/30/45/60 分钟，默认 30；休息提醒：30/45/60/90 分钟，默认 60。使用现有文字框，只显示正文、不显示角色称呼，缩小桌宠时实际字号仍至少为 14，并自动换行；支持自动淡出和双击关闭，同时到期合并，不覆盖已有警告或对话。
- 额度、喝水和休息主动提示统一使用原有常规姿态，不播放轻拍动作，也不从自主动作池抽取动作。
- 提示期间暂停自主走动；贴边时喝水、休息提醒会临时移入屏幕显示，结束后回到原位置，随机额度提示仍不打断贴边。真正隐藏、休眠和退出会取消提示，恢复后重新计时，不补发旧提醒；打开用量面板或重复请求显示不重置计时。
- 本地 `layout.json` 新增可选字段 `cloudMode`、`cloudRandomMinutes`、`drinkReminderEnabled`、`drinkReminderMinutes`、`restReminderEnabled`、`restReminderMinutes`。随机分钟字段保存区间下限（3/5/10）；缺失或无效偏好回退默认。倒计时、手动显隐覆盖和临时动作不持久化。

宿主 `--smoke-test` 包含可控时间的提醒与常规姿态检查，产出 `report.json` 与提醒截图。检查必须使用独立的绝对路径 `--data-dir`，避免覆盖真实偏好；拖拽检查需要可接收鼠标捕获的交互桌面。

## 自主活动

构建包含完整 `IDEL` 待机目录，以及原有的 `State`、`MOVE` 资源。自娱自乐、侧身互动、无聊、吹泡泡、比心、喵喵、探看、下蹲、网球和哈欠均有自主入口；坐下和躺下按顺序衔接，只有循环段的动作也能直接开始。

启用“自主活动”后，每 15 秒在空闲时尝试移动、待机或短暂停留。待机池每轮随机遍历所有动作与状态版本，再开始下一轮；不修改角色心情或养成数值。动作有开始段时先播放开始段，循环 2–4 次后结束；单段动作播放一次。缺少同状态衔接段时复用同动作的常规版本。移动继续遵守原核心的方向、边界和爬行条件。

贴边后会锁定贴边姿态并暂停自主移动、待机、生活提醒和用量警告；只有用户开始拖动角色才解除锁定，隐藏恢复、系统唤醒和重启都不会自动取消。关闭自主活动、拖动、缩放、打开菜单、隐藏、休眠或退出会取消正在播放的自主序列；未贴边时提醒和用量警告优先。所有新行为仅是动画播放，不启用投喂、睡眠、工作或收益计算。

拖放吸附范围从原画布的 50 单位缩小为 12 单位（默认 220 像素桌宠约从 22 像素缩至 5 像素），保留靠墙但不隐藏的停放区域。该区域内的移动选择优先采用满足原核心条件的左右爬墙动作；真正贴边、拖出屏幕后的吸附和多屏定位仍保留。

冒烟检查逐一启动所有动作/状态组合，完整验证循环段和坐躺序列，并验证提醒抢占和旧回调取消；动作目录与序列写入 `autonomy-catalog.json`。

## 独立版本清单

`pet_host/extension.json` 是桌宠版本的唯一来源，当前正式版为 `0.2.2`，最低兼容主程序 `1.16.2`，以支持右键新增和单独关闭实例；旧主程序继续使用兼容的桌宠 `0.2.1`。协议版本为 `1`。桌宠更新通道可在设置页独立选择，默认检查稳定扩展：

- `version`：桌宠自己的语义化版本，不与 `APP_VERSION` 同步递增。
- `protocol`：桌宠与主程序的通信协议版本。改变协议时应同步评估主程序桥接兼容性。
- `platform`：目前为 `win-x64`。
- `min_app_version`：最低兼容主程序版本，包含此版本。首次发布前应核对首个支持该协议的公开主程序版本。
- `max_app_version`：可选的不兼容主程序起始版本，不包含此版本；省略表示没有已知上界。

兼容性由协议、平台和主程序版本区间共同决定；扩展版本号不参与主程序版本比较。已安装的旧试用包没有独立版本号时仍按原协议运行，可升级到新的独立包。

## 构建与验证

需要项目 Python 开发依赖和 .NET SDK 8 或更新版本。构建默认包含 .NET 运行时，使用者不必安装 SDK 或运行时。

```powershell
python scripts/build_vpet.py
python examples/vpet_preview.py --verify
python -m pytest tests/test_pet_extension.py tests/test_packaging.py tests/test_update.py -q
python scripts/build_release.py --stage pet
```

输出目录 `dist-pet/` 同时包含兼容旧客户端的完整 ZIP、供双角色安装复用本地动画的 Host ZIP、VPet 与鲸鱼娘两个单角色 ZIP、用于小流量检查更新的 `extension.json`，以及覆盖全部附件的 `SHA256SUMS.txt`。新客户端首次只下载所选角色；已安装一个角色时可单独下载另一个角色并合并，缺少单角色附件的旧版本回退完整包。这些文件不进入主安装器；主程序构建也不编译桌宠。

## 单独提交与发布

1. 只提交本次桌宠相关源码、资源维护代码、测试和说明；不要把本地构建缓存提交进仓库。
2. 普通开发提交不递增公开版本。准备发布时，根据上一个已发布的 `pet-v*` 版本统一调整清单的 `version`，不调整主程序版本文件。
3. 编写 `release-notes/pet-v<版本>.md`，沿用项目格式，包含更新类型、变更、实际验证结果及兼容范围。发布工作流拒绝缺失说明的版本。
4. 按 `GIT_VERSION_AND_MERGE_RULES.md` 提交、推送，并仅在准备公开发布时创建和推送与清单一致的 `pet-v<版本>` Tag。
5. `pet-release.yml` 只构建并上传桌宠的完整包、Host 包、清单和校验文件，`make_latest: false` 保留主程序 Latest；发布后检查正文、附件和真实下载安装路径。

主程序继续使用 `v<版本>` Tag 和原发布流程；桌宠发布不触发面板安装包构建。开启“启动后自动检查”时，主程序也会检查已安装的桌宠扩展，发现兼容新版后提示，确认后进入桌宠设置页更新。同一桌宠版本每次运行只自动提示一次，暂不更新会在下次启动时再次提醒；设置页仍可手动检查。主程序正在更新时先完成主程序更新，重启后再按新主程序的兼容范围检查桌宠。不自动安装未选择的扩展，也不强制更新主程序以安装不兼容桌宠。

## 更新失败与卸载

更新时暂停桌宠，保留 `VPET_ENABLED` 和所有面板设置。双角色安装在资源版本、文件数量、总大小和 SHA256 全部一致时，可由 Host 小包复用本地动画；单角色更新下载对应角色包。下载、校验、资源复制和解压均在替换前完成；替换时旧包先移到同目录备份，失败立即恢复。若进程恰好在两次重命名之间退出，下次启动恢复备份。新宿主启动失败时仍使用原悬浮球和面板。

卸载只删除扩展、旧试用安装包中的 `pet/`、替换备份和动画缓存；保留 `vpet/` 中的偏好、账户、用量与主题。SHA256 提供文件完整性校验，不等同于独立签名。
