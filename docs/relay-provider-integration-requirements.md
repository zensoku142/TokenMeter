# TokenMeter 第三方中转服务商接入需求文档

## 1. 文档目的

在 TokenMeter/TokenSpider 中接入首个第三方中转服务商（当前服务商为 NayutoAI），同时保留后续接入更多中转服务商的扩展能力。

本需求只扩展数据源和服务商适配，不改变现有面板布局、交互方式、小米与 DeepSeek 的业务行为。

## 2. 已确认目标

1. 在现有服务商切换入口中增加中转服务商。
2. 中转服务商使用自己的账户余额、消费金额、请求用量和分时数据。
3. 中转分时继续使用 TokenMeter 当前小米/DeepSeek 的“今日分时”图表和分钟详情浮层。
4. 悬浮球完全复用当前小米金额球的样式、尺寸、位置、交互和信息层级，只替换中转数据和币种。
5. 中转登录沿用“小米式”的用户体验：程序打开隔离浏览器，用户完成登录，程序自动捕获所需登录凭证。
6. 当前中转与小米、DeepSeek 的取数和分时计算逻辑相互独立，禁止直接套用其他服务商的字段解释或金额计算公式。
7. 后续增加其他中转服务商时，应主要增加服务商配置/适配代码，不应在界面层散落大量服务商判断。

## 3. 明确不做的内容

- 不嵌入或仿制第三方服务商的网站控制台。
- 不新增侧栏、钱包、充值、使用记录等第三方网站页面。
- 不重新设计 TokenMeter 主面板。
- 不改变小米、DeepSeek 已有接口、缓存、轮询、分时或悬浮球逻辑。
- 不为了本需求进行无关重构、统一命名、批量格式化或更换框架。
- 未经确认不新增数据库结构或外部依赖。

## 4. 设计原则

### 4.1 兼容优先

- 现有用户的服务商选择、刷新、日期切换、主题切换、悬浮球和后台采集习惯保持不变。
- 未配置中转账号时，小米和 DeepSeek 应与改造前完全一致。
- 中转请求失败不得清空其他服务商缓存，也不得把中转结果写入小米或 DeepSeek 的展示状态。

### 4.2 轻量适配

优先复用项目已有服务商抽象、任务调度、缓存、凭证存储和界面 ViewModel。只有现有结构确实无法承载时，才增加最小的适配层。

建议把以下差异留在服务商适配层，而不是放到 UI 中：

- 服务商标识和显示名称
- Base URL 和接口路径
- 登录凭证类型
- 请求头构造
- 分页规则
- 响应字段解析
- Token 口径
- 实际金额和币种
- 服务商能力，例如余额、分钟用量、实际账单

不得为了“以后可能使用”建立复杂插件系统；当前只需要形成清晰、可增加第二个中转适配器的边界。

## 5. 数据来源

### 5.1 请求明细/今日分时

已确认优先使用：

```text
GET https://nayutoai.xyz/portal/user/usage?page=1&page_size=50
```

该接口按请求提供时间、Token、缓存和实际消费信息，适合作为分钟明细的主数据源。

实施时必须先阅读并以以下资料为准：

```text
C:\Users\Administrator\Desktop\中转请求和响应参数.txt
```

必须核实：

- 实际响应的列表节点和分页字段。
- 时间字段名称、时区和格式。
- Request ID 或其他稳定唯一键。
- 输入、缓存输入、输出 Token 的真实口径。
- 实际消费金额字段、类型、精度和币种。
- 余额与账户信息应调用的实际接口。
- 认证失效时的状态码和响应体。

禁止仅凭本需求文档猜测不存在的字段。

### 5.2 分页与时间范围

- 单页按服务商支持的最大安全值请求，当前示例为 `page_size=50`。
- 为得到完整日期/分钟数据，应继续翻页，直到列表为空、到达总页数，或记录时间已经早于所需窗口。
- 必须设置最大页数或其他终止保护，防止异常响应导致无限翻页。
- 轮询时允许优化为增量拉取，但必须保证跨页、跨分钟及日期边界不漏数。

### 5.3 去重

- 优先使用服务商返回的稳定 Request ID 去重。
- 如果实际响应没有稳定唯一键，必须根据真实字段设计稳定组合键，并在代码注释/测试中说明依据。
- 同一请求被分页重复返回或被多轮刷新拉到时只能计入一次。
- 去重应按服务商隔离，不能与小米或 DeepSeek 共用请求命名空间。

## 6. 中转分时计算规则

### 6.1 分钟归桶

- 按请求实际发生时间归入 `HH:mm` 分钟桶。
- 时间解析必须尊重响应中的时区；若响应不带时区，应从实际接口行为确认，不能直接假定本地时间。
- 界面日期和分钟边界必须与 TokenMeter 当前日期切换逻辑一致。

### 6.2 分钟详情字段

中转分钟悬浮详情与现有小米/DeepSeek保持同一结构：

```text
18:01                         总计 12.60万
■ 输入（命中缓存）             11.21万
■ 输入（未命中缓存）            1.31万
■ 输出                          0.07万
────────────────────────────
缓存命中率                       89.5%
────────────────────────────
本分钟消耗金额                  $0.0861
```

字段定义：

- 输入（命中缓存）：本分钟所有请求的缓存命中输入 Token 合计。
- 输入（未命中缓存）：本分钟所有请求的非缓存输入 Token 合计。
- 输出：本分钟所有请求的输出 Token 合计。
- 总计：以上三项合计，展示值允许按现有规则格式化。
- 缓存命中率：`命中缓存输入 / (命中缓存输入 + 未命中缓存输入)`；分母为零时按现有 UI 约定展示 0% 或占位符。
- 本分钟消耗金额：本分钟各请求“服务商实际消费金额”之和，不使用 DeepSeek 或小米价格表重新估算。

重要口径：必须根据真实响应确认 `input_tokens` 是否已经包含缓存 Token。如果接口已经把非缓存输入与缓存输入分别返回，则直接映射，不能再次相减；如果缓存是输入的子集，才计算 `未命中输入 = 输入总量 - 缓存输入`。此口径必须用附件样例编写单元测试。

### 6.3 金额精度

- 主面板今日金额、余额和统计卡片按现有金额格式展示，币种为美元 `$`。
- 分钟金额保留足够识别小额消费的精度，目标效果为 `$0.0861`；最终小数位应复用现有格式化能力或按实际产品规则统一。
- 计算过程使用十进制金额类型，禁止使用二进制浮点直接累计账单金额。

## 7. 登录与凭证获取

### 7.1 用户体验

中转登录体验与小米一致：

1. 用户在 TokenMeter 中选择连接中转服务商。
2. 程序打开隔离的登录浏览器。
3. 用户在第三方页面自行完成登录和可能的验证码操作。
4. 程序监听真实门户请求，自动获取请求所需认证信息。
5. 程序调用轻量接口验证凭证有效性。
6. 验证成功后安全保存，关闭或提示用户关闭登录浏览器。
7. 界面显示连接成功并开始首次同步。

### 7.2 与小米的区别

- 只复用小米的登录交互和浏览器会话能力，不假定凭证内容相同。
- 小米如果使用 Cookie，中转根据实际请求重点捕获 `Authorization: Bearer ...`；是否还需要 Cookie、CSRF 或其他请求头必须以真实请求为准。
- 应优先监听 `/portal/auth/me`、`/portal/user/usage` 等真实 API 请求并提取最小必要认证信息，禁止抓取或保存无关浏览数据。

### 7.3 凭证安全

- 复用项目现有 Windows Credential Manager/安全凭证存储方案。
- Bearer Token、Cookie、登录响应和用户隐私信息不得写入普通配置、日志、异常堆栈、测试快照或 Git。
- 日志只能输出脱敏后的服务商、请求结果和错误分类。
- 用户提供过的示例凭证视为已暴露样例，不得写入代码或测试；上线使用前应重新登录或轮换凭证。

## 8. UI 与交互要求

### 8.1 主面板

- 在现有服务商下拉框中增加“中转”显示项；内部 ID 应稳定且与显示名称解耦。
- 主面板仍使用当前 TokenMeter 结构，不新增第三方控制台页面。
- 继续展示今日使用金额、账户余额、本月累计、近 7 天金额、Token 活动和使用统计。
- 对于来自服务商实际账单的金额，可在现有“估算”位置显示“平台账单”，但不得改变控件位置或布局。
- 主题、关闭、刷新、设置和日期操作保持原样。

### 8.2 今日分时

- 复用现有“今日分时”按钮、日期切换、图例、柱形图、缩放/滚动条和悬停详情。
- 图例颜色与小米/DeepSeek一致：命中缓存、未命中缓存、输出三类不增加新颜色体系。
- 无数据、加载中、请求失败和凭证失效的表现优先复用现有组件。
- 中转分时无数据时不得回退显示其他服务商的数据。

### 8.3 悬浮球

- 完全复用小米当前金额悬浮球组件。
- 不改变大小、外框、玻璃效果、阴影、字体、分隔线、拖动、点击、展开/收起和置顶行为。
- 不显示百分比、不新增进度环、不增加中转专属颜色或徽标。
- 只替换为中转的“今日使用金额”和“账户余额”，币种显示 `$`。

## 9. 后台采集与状态隔离

- 中转应加入现有已配置服务商的后台采集机制，不要求用户先切换到该服务商才更新。
- 当前展示服务商与后台正在采集的服务商必须解耦。
- 每次完成结果都可以写入对应服务商缓存，但只有结果所属服务商仍是当前展示服务商时才刷新可见 UI。
- 必须保留现有防重入、请求在途标记和迟到结果保护，防止旧请求覆盖新服务商界面。
- 各服务商的缓存、错误、最后更新时间、分钟数据和凭证状态必须隔离。
- 中转失败不能阻塞小米或 DeepSeek 的下一轮采集。
- 网络失败时保留最后一次成功数据，并显示现有风格的状态提示。

## 10. 推荐适配边界

实施时先搜索现有实现。如果项目已有 provider/adapter/fetcher 抽象，应直接扩展；不存在时，只引入最小边界，例如：

```text
RelayProviderConfig
  - provider_id
  - display_name
  - base_url
  - currency
  - auth_strategy
  - capabilities

RelayProviderAdapter
  - validate_credentials()
  - fetch_account_summary()
  - fetch_usage_page()
  - normalize_usage_record()
```

以上只是职责示意，不是强制类名。实际命名必须服从仓库现有风格，且应优先复用已有 DTO、缓存和任务对象。

UI 只消费统一后的展示数据，不直接解析第三方 JSON，也不直接拼接认证请求头。

## 11. 异常处理

- 401/403：标记凭证失效，保留历史缓存，提示重新连接。
- 429：按响应头或已有退避机制处理，不高频重试。
- 5xx/超时/断网：记录脱敏错误，保留缓存，下轮继续采集。
- 单条脏数据：在不影响整页有效数据的前提下跳过并记录可定位的脱敏信息。
- 分页中途失败：不得提交不一致的覆盖结果；应沿用项目当前原子更新或最后成功快照方式。
- 字段缺失：区分可选字段和核心字段，核心账单字段缺失时不能默认为零造成错误统计。

## 12. 测试要求

### 12.1 单元测试

至少覆盖：

- 附件中的真实响应样例解析。
- 分页终止和跨页去重。
- 相同请求多次轮询不重复累计。
- 时间解析、跨分钟和跨日期边界。
- 缓存输入口径的两种可能语义，最终只保留真实接口对应规则。
- 分钟 Token 合计、缓存命中率和实际金额汇总。
- 金额十进制精度与格式化。
- 空列表、缺失可选字段、核心字段异常。
- 401、403、429、5xx和超时。
- 多服务商并发/迟到结果不能串数据。

### 12.2 回归测试

- 运行项目现有完整测试集。
- 专门验证小米登录、取数、分时和悬浮球未变化。
- 专门验证 DeepSeek登录、取数、费率/分时和悬浮球未变化。
- 验证切换顺序“小米 → 中转 → DeepSeek → 中转”不会串缓存或串状态。

### 12.3 手工验收

- 使用真实新凭证完成浏览器登录捕获。
- 与第三方网站相同日期的余额、今日金额、分钟 Token 和分钟金额抽样核对。
- 检查刷新、日期切换、主题切换、后台更新和悬浮球。
- 断网、退出登录、Token 失效后界面可恢复且不丢历史缓存。

## 13. 验收标准

1. 用户可以通过 TokenMeter 打开浏览器登录中转，程序自动获得并安全保存有效凭证。
2. 中转主面板沿用现有 TokenMeter 布局，能显示美元余额、今日金额和统计数据。
3. “今日分时”使用中转请求明细生成，分钟详情字段、顺序和样式与小米/DeepSeek一致。
4. 分钟 Token、缓存命中率和金额能与真实明细抽样核对。
5. 悬浮球外观和交互与小米完全一致，只显示中转金额数据。
6. 多次刷新、分页和后台轮询不会重复累计。
7. 切换服务商和迟到请求不会导致数据串台。
8. 小米和 DeepSeek 的原有功能、接口、显示和使用习惯保持不变。
9. 凭证不出现在代码、配置、日志、测试数据或提交记录中。
10. 新增代码通过相关单元测试和现有回归测试；无法执行的验证必须在交付说明中逐项列出。

## 15. 实施前必须确认的开放项

以下内容不得在未读取附件和代码时自行假定：

- 中转账户信息/余额的准确接口。
- `usage` 响应的准确字段名和 Token 口径。
- 时间字段时区。
- Bearer 之外是否还需要 Cookie、CSRF 或其他请求头。
- 中转是否提供历史日汇总接口，还是必须由请求明细聚合。
- 请求接口的限流规则和允许轮询频率。
- 账号退出、Token 到期和刷新机制。

这些项目应在实现阶段通过附件、浏览器真实请求和只读接口验证后落实到代码与测试中。
