# TokenMeter 额度监控迭代方案

这是 2026-09-05 首批工作的规划与验收记录；后续平台接入、纯图标导航和 Claude OAuth 直读等实现已继续演进。当前配置方式以 [README](../README.md)、[平台接入说明](codexbar-provider-coverage-2026-09-05.md)和 [Gemini / Claude 指南](gemini-quota-2026-09-05.md)为准。

本批次类型：功能新增、Bug 修复、功能优化、文档更新。

## 产品方向

把 TokenMeter 做成 Windows 上轻量、可信的多平台额度仪表盘：先回答“还能使用多少、什么时候恢复、数据从哪里来”，再提供费用与历史分析。保留现有悬浮球、主面板、主题、语言和桌宠，不重写已有架构。

每个供应商独立连接、隔离缓存和失败状态。展示严格区分订阅配额、API 余额、密钥预算和 Token 实际用量；未提供的字段保持不可用。人民币和美元不相加，也不从余额或本地 Token 反推订阅剩余量。

## 本轮交付

- 扩展官方接口与可核实客户端数据源，配置、后台同步、主面板沿用 Provider 注册表。
- OpenRouter：普通 Key 的预算剩余与 UTC 当日、本月、累计费用；未设预算上限时不显示虚构余额。
- Moonshot / Kimi API：国内人民币、国际美元可用余额，使用平台直接给出的可用值。
- Claude Code：官方状态栏快照，只保存必要额度字段；15 分钟未更新则过期；未指定账号标识时禁用缓存复用。
- GitHub Copilot：实验性读取第一方客户端所用额度接口，兼容 AI credits、旧免费套餐、无限量和按类别缺失的窗口。
- GLM / Z.ai Coding Plan：读取官方用量插件使用的接口，仅显示已确认的套餐及工具调用额度比例；不推算时间窗口、重置日期或 Token 绝对量。
- 设置页解释平台数据范围、提供官方页面入口，后台同步选项分行排列；长平台名在展开菜单中完整显示。
- 对于仅提供摘要的平台，图表明确提示没有历史明细。支持文案包含简中、繁中、英文、日文、韩文。
- 修复异常数值、畸形用量数组、意外刷新错误丢失缓存、国际余额离线时币种变更和设置切换时资源未释放问题。

完整来源、每个平台的接入步骤与限制见[供应商研究](provider-support-research-2026-09-05.md)。

## 后续批次及验收条件

| 顺序 | 目标 | 实施前条件 | 验收要求 |
| --- | --- | --- | --- |
| 1 | 现有新适配器实账号验收 | 用户提供对应账号的合法登录或配置；不把测试令牌当真账号 | 逐字段与官方控制台比对，覆盖失效、限流、恢复、换账号及跨月 |
| 2 | OpenAI / Anthropic 组织用量与费用 | 组织管理员 API 权限与官方字段合同 | 完整分页，明确 USD 单位与时区，不混入个人订阅额度 |
| 3 | Gemini CLI / Code Assist | 核实 OAuth、项目标识与刷新周期 | 正确识别不同账号和项目的模型配额，令牌过期可恢复 |
| 4 | MiniMax Token Plan | 核实当前官方 CLI 的结构化额度输出 | 新旧套餐分别验证，避免沿用退役的请求计费规则 |
| 5 | Windsurf / Devin、SiliconFlow 国内 | 有可核实且仍在服务的读数入口 | 有来源、权限边界和失败恢复，不调用已退役接口 |
| 6 | 多账户总览与提醒 | 各供应商数据语义和可靠性已通过验收 | 显示来源和时间；过期数据不触发额度耗尽提醒；重复提醒去重 |

每个批次只增加当前需求必要的代码；已有 Provider 能力字段可复用时不引入另一套插件框架。新增依赖须确有必要，不能通过大量轮询或额外模型推理获取额度。
