# WorkBuddy 积分监控

在 TokenMeter 的「账户连接」中选择 WorkBuddy，通过专用小窗登录国内个人版。进入「套餐与积分」后，回到 TokenMeter 完成采集。TokenMeter 在小窗关闭后验证网页余额，再保存连接。

连接后，选中 WorkBuddy 或将它加入后台采集。TokenMeter 从网页版读取剩余积分，按官网「产品 = WorkBuddy」的筛选口径汇总今日、本月和按模型的积分消耗。明细读取失败时，面板仍可显示本次取得的余额，并标记最近一次成功读取的消耗数据为缓存。

网页会话失效时，在「账户连接」中重新连接。积分和调用次数按网页口径显示。

## 面板说明

积分不是 Token，也不是金额：面板上的数值、坐标轴和悬停提示都使用「积分」单位，不做万/亿缩写，也不加货币符号。

- 左上主数值是剩余积分（接口的 `TotalCredits`），下方两张小卡是套餐基础积分和平台奖励积分。卡片可见文字只显示总额，`已用 / 总计` 的完整说明在悬停提示和「额度明细」中。
- 当接口返回的「购买积分」大于 0 时，剩余积分下方会多一行「含购买积分 …」，让自购积分在卡片区可见。卡片区只有一主两副三个位置（四张并列时每张约 46px，而标签需要 72px），因此不再拆第四张卡，其余分组仍可在「额度明细」查看。
- 右上「近 7 天积分消耗」按中国时区今天向前六天绘制每日积分柱状图。
- 中间「积分活动」按当前自然月真实天数（28／29／30／31）绘制每日积分柱状图。今天有一条与柱子等高的浅色外框；未来日期不绘制消耗，也不会在悬停时显示为 0。日期刻度按「每刻度至少 22px」疏化，窄窗口只隔天标注，今天与月末始终保留。
- 「积分活动」右侧是「模型积分消耗」：左栏约 60% 宽度放月图与「额度明细」，右栏约 40% 按积分降序列出模型名、消耗积分、占比条和占比。占比分母是同一账号、同一时段的全部模型积分，包含未滚动到的行；积分与占比右对齐，长模型名省略显示并保留完整悬停提示。模型较多时只有列表内部滚动，标题、模型总数和「本月／今日」切换固定不动。
- 右栏默认「本月」，切换到「今日」只更新右栏并回到首行，左栏始终是整月图。今日模型来自同一批使用明细，按中国时区自然日切分，不额外请求；底部「使用模型数」仍按本月口径，右栏的模型总数随所选时段变化。
- 首次读取显示「正在读取模型积分」；成功返回但没有模型记录时显示「本月暂无模型消耗」或「今日暂无模型消耗」。使用明细刷新失败而缓存仍属同一时段时，列表继续显示并标注「缓存 · 2026年11月」或「缓存 · 2026-11-11」；缓存跨月显示「统计待更新 · 缓存为 …」，跨日时「今日」不再沿用昨天的模型，提示「使用明细暂不可用」。
- 底部五项统计依次为：本月消耗积分、今日消耗积分、本月调用次数、使用模型数、本月活跃天数。
- 悬浮球与轻底细环显示剩余积分数值。轻底细环宽度只有 42px 时按「完整值 → 取整值 → k/M」的顺序择一显示，保证读数不被省略号截断（例如 `2868`、`12346`、`123k`、`1.23M`），完整数值仍在悬停提示与无障碍名称中。

月初切换月份后，如果只拿到上月的缓存，本月图会显示「统计待更新 · 缓存为 …」，不会把上月数据当成本月已完成的统计。缓存不含完整日期范围时不会补零，只有本轮完整成功的统计才把缺失日期显示为零消耗。

面板只读取已有的积分接口和统计序列，不额外请求、不写数据库，也不改变其他平台的取数口径。
